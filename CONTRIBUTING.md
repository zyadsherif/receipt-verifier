# Contributing

Thank you for improving receipt verification safely.

1. Open an issue for significant behavior or policy changes.
2. Fork the repository and create a focused branch.
3. Add tests for every rule, parser, provider, or security change.
4. Use only synthetic, consented, or irreversibly redacted receipt fixtures.
5. Run `npm run quality`.
6. Submit a pull request describing behavior, risk, and verification.

Never commit API keys, real customer receipts, unmasked financial identifiers, or private evaluation data. By contributing, you agree that your contribution is licensed under MIT.
